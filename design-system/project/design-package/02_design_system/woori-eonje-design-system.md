# 우리 언제? 디자인 시스템

> 기간 기반 모임 시간 조율 서비스 **우리 언제?**의 브랜드 및 UI 디자인 기준 문서입니다.  
> 본 문서는 Claude Design 또는 디자이너/개발자에게 전달해도 바로 기준으로 사용할 수 있도록, 로고·폰트·컬러·컴포넌트·UI/UX 원칙을 함께 정리합니다.

---

## 1. 디자인 방향 요약

### 브랜드 한 줄 정의
**흩어진 약속 답변을 정리해, 모두에게 가장 잘 맞는 시간을 찾아주는 모임 조율 서비스**

### 무드 키워드
- **Clean**: 정보가 먼저 읽히는 깔끔한 구조
- **Playful**: 물음표, 말풍선, 둥근 시간 슬롯으로 가벼운 리듬감 부여
- **Utility**: 실제 조율 흐름과 사용성을 우선하는 기능형 UI
- **Limited Color**: 색을 많이 쓰지 않고 필요한 지점에만 포인트 사용
- **Cool Pastel**: 누리끼리한 베이지가 아닌 쿨톤 화이트/라이트그레이 기반

### 피해야 할 방향
- 누리끼리한 크림/베이지 감성
- 보편적인 AI SaaS 랜딩 느낌
- 3D 오브젝트, 캐릭터, 과한 그라데이션
- 기능 카드 3개 나열 중심의 흔한 랜딩 구성
- 캘린더 아이콘 중심의 식상한 일정 앱 이미지

- 그림자, 그라데이션, 외곽선 효과 추가 금지
- 캘린더 아이콘과 직접 결합 금지
- 복잡한 사진/패턴 배경 위 사용 금지

## 3. 폰트 시스템

### 기본 폰트
**Pretendard**

### 폰트 사용 원칙
- Pretendard 단일 패밀리 사용
- 제목은 굵고 자간을 좁게 설정해 로고와 연결감 유지
- 본문은 행간을 넉넉하게 설정해 모바일에서도 읽기 편하게 구성
- 장식용 폰트, 손글씨 폰트, 세리프 폰트는 사용하지 않음

### 타이포그래피 스케일

| 용도 | Size | Weight | Line-height | Letter-spacing | 사용 예시 |
|---|---:|---:|---:|---:|---|
| Display / Logo-like | 52px~92px | 900 | 0.98 | -0.075em | 스플래시, 랜딩 큰 로고 |
| Heading 1 | 32px | 800 | 1.35 | -0.04em | 페이지 메인 제목 |
| Heading 2 | 24px | 700 | 1.4 | -0.035em | 섹션 제목 |
| Heading 3 | 20px | 700 | 1.45 | -0.03em | 카드 제목 |
| Body 1 | 16px | 400 | 1.65 | -0.02em | 본문 설명 |
| Body 2 | 14px | 400~600 | 1.6 | -0.015em | 보조 설명, 목록 |
| Caption | 12px | 500 | 1.5 | -0.01em | 도움말, 메타 정보 |
| Button | 14px~16px | 700 | 1 | -0.015em | 버튼 텍스트 |

### 한글 자간/행간 기준
- 큰 제목은 `letter-spacing: -0.04em ~ -0.075em`
- 일반 제목은 `letter-spacing: -0.03em ~ -0.04em`
- 본문은 `letter-spacing: -0.015em ~ -0.02em`
- 본문 행간은 최소 `1.6` 이상 권장
- 버튼은 한 줄 중심 정렬이므로 `line-height: 1` 또는 버튼 높이 기준 중앙 정렬

## 4. 컬러 시스템

### 핵심 방향
화이트/라이트그레이 기반 위에 **Forest Green**을 주요 액션 컬러로 사용하고, **Poppy**는 로고 물음표와 작은 강조에만 제한적으로 사용합니다.

### 컬러 토큰

| 토큰 | HEX | 용도 |
|---|---|---|
| Primary / Forest | `#1A9562` | 주요 버튼, 활성 상태, 가능 상태, 확정 액션 |
| Primary Hover | `#14784F` | Primary hover |
| Primary Soft | `#EAF7F1` | Primary 약한 배경, 선택 전 강조 영역 |
| Accent / Poppy | `#FF6B6B` | 로고 물음표, 파비콘, 작은 포인트 |
| Accent Soft | `#FFF0F0` | Poppy 약한 배경 |
| Baby Blue | `#D6E7FF` | 그래픽 보조, 빈 상태 장식 |
| Lavender | `#E6DBF7` | 그래픽 보조, 온보딩 장식 |
| Mango | `#F5AB54` | 애매 상태 |
| Mango Soft | `#FFF7E8` | 애매 상태 배경 |
| Background | `#F6F8FA` | 전체 배경 |
| Surface | `#FFFFFF` | 카드, 폼, 패널 |
| Line | `#E5E7EB` | 기본 구분선 |
| Line Dark | `#D1D5DB` | 비활성/불가 구분선 |
| Text Primary | `#333333` | 주요 텍스트 |
| Text Secondary | `#6B7280` | 보조 텍스트 |
| Text Muted | `#9CA3AF` | 비활성 텍스트 |
| Error | `#EF4444` | 오류, 삭제 위험 액션 |

### 컬러 사용 비율
| 색상군 | 비율 |
|---|---:|
| White / Light Gray | 80% |
| Forest | 10% |
| Poppy | 5% |
| Baby Blue / Lavender | 5% |

### 사용 주의
- Poppy를 CTA 버튼에 남용하지 않음
- Mango는 상태값 중심으로만 사용
- Baby Blue와 Lavender는 장식성 보조 컬러로만 사용
- 베이지/크림 계열 배경은 사용하지 않음

## 5. Radius / Spacing / Layout

### Radius 토큰
| 토큰 | 값 | 용도 |
|---|---:|---|
| xs | 8px | 작은 태그, 보조 요소 |
| sm | 12px | 작은 버튼, 작은 슬롯 |
| md | 16px | 기본 버튼, 입력 필드 |
| lg | 20px | 기본 카드 |
| xl | 28px | 큰 패널, 섹션 |
| pill | 999px | 배지, 칩 |

### Spacing 토큰
`4px / 8px / 12px / 16px / 20px / 24px / 32px / 48px / 64px / 80px`

### 레이아웃 기준
| 항목 | 기준 |
|---|---:|
| Desktop max-width | 1120px ~ 1200px |
| Header height | 64px ~ 72px |
| Section gap | 80px ~ 120px |
| Card gap | 16px ~ 24px |
| Mobile padding | 20px |
| Mobile CTA | 하단 고정 사용 가능 |

### UI 레이아웃 원칙
- 데스크톱보다 모바일 참여자 화면을 먼저 고려
- 시간 슬롯은 손가락으로 누르기 쉬운 크기로 설계
- 카드 간격은 넉넉하게 두되 정보 밀도는 유지
- 그림자는 거의 사용하지 않고 border 중심으로 구분

## 6. 버튼 시스템

### 공통 기준
| 항목 | 기준 |
|---|---:|
| Height | 44px ~ 48px |
| Radius | 14px ~ 16px |
| Font | Pretendard 14px~16px / 700 |
| Letter-spacing | -0.015em |

### 버튼 종류

| 타입 | 스타일 | 용도 |
|---|---|---|
| Primary | Forest 배경 + 흰색 텍스트 | 모임 만들기, 제출하기, 확정하기 |
| Secondary | Primary Soft 배경 + Forest 텍스트 | 취소, 이전, 보조 액션 |
| Outline | 흰색 배경 + Forest border | 자세히 보기, 응답 수정, 링크 복사 |
| Ghost | 투명 배경 + Forest/차콜 텍스트 | 더보기, 건너뛰기 |
| Danger | 흰색 배경 + Error 텍스트 | 삭제, 초기화 |
| Disabled | Light Gray 배경 + Muted 텍스트 | 비활성 상태 |

### 버튼 UX 기준
- 한 화면의 Primary 버튼은 1개만 두는 것을 원칙으로 함
- Poppy 버튼은 사용하지 않음
- 위험 액션은 Poppy가 아니라 Error 컬러를 사용해 브랜드 포인트와 분리

## 8. 시간 슬롯 UI

### 기본 슬롯
- Background: `#FFFFFF`
- Border: `1px solid #E5E7EB`
- Radius: `12px ~ 14px`
- Text: `#333333`
- 최소 높이: 56px 이상 권장

### 상태별 슬롯
| 상태 | 스타일 | 설명 |
|---|---|---|
| 기본 | 흰색 + 회색 border | 아직 선택하지 않은 시간 |
| 가능 | Forest Soft 배경 + Forest border | 참석 가능한 시간 |
| 선택됨 | Forest 배경 + 흰색 텍스트 | 현재 선택/확정된 가능 시간 |
| 애매 | Mango Soft 배경 + Mango border | 가능하지만 확실하지 않은 시간 |
| 불가 | Gray 배경 + Muted 텍스트 | 참석 어려운 시간 |

### 시간 슬롯 UX 기준
- 가능/애매/불가 상태는 색상만으로 구분하지 않고 텍스트 또는 라벨을 함께 사용
- 모바일에서는 탭 선택 + 빠른 선택을 우선
- 드래그 선택은 2차 기능으로 검토
- 선택 완료 버튼은 모바일 하단 고정 사용 가능

- 백엔드 상태명을 그대로 노출하지 않음

## 11. Empty / Loading / Error

### Empty
예시 문구:
- 아직 만든 모임이 없어요
- 아직 응답한 사람이 없어요
- 모두가 가능한 시간이 없어요

### Loading
- 카드 스켈레톤
- 시간 슬롯 스켈레톤
- 추천 계산 중 안내

### Error
예시 문구:
- 초대 링크가 만료되었어요
- 존재하지 않는 초대 링크예요
- 일시적으로 정보를 불러오지 못했어요

### UX 기준
- 빈 화면에서는 다음 행동을 함께 제공
- 오류 문구는 기술적 원인보다 사용자가 할 수 있는 행동을 안내
- 그래픽은 파스텔 도형 정도로 제한
- 사람 일러스트, 3D 캐릭터, AI풍 이미지 사용 금지

## 13. 문장 톤

### 기본 톤
친근하지만 과하게 감성적이지 않게.  
기계적인 계산 표현보다 사용자가 바로 이해할 수 있는 문장을 사용합니다.

### 좋은 톤
- 가능한 시간을 골라주세요
- 가장 잘 맞는 시간을 찾았어요
- 아직 응답한 사람이 없어요
- 이 시간으로 확정할까요?
- 응답 마감일까지 함께해주세요

### 피할 톤
- 최적의 일정을 산출했습니다
- 참여자 응답 데이터가 없습니다
- 스케줄 매칭을 시작합니다
- 시스템이 분석을 완료했습니다
- 일정을 확정 처리합니다

## 15. Claude Design 작업 기준

### 디자인 방향
- 쿨톤 화이트/라이트그레이 기반의 깔끔한 서비스 UI
- Forest Green을 주요 액션 컬러로 사용
- Poppy는 로고 물음표, 파비콘, 작은 포인트에만 제한적으로 사용
- Baby Blue와 Lavender는 장식 도형 또는 빈 상태 그래픽 보조로만 사용
- 누리끼리한 베이지/크림 배경 금지
- 과한 그라데이션, 3D 캐릭터, AI SaaS 템플릿 느낌 금지

### UI/UX 기준
- 사용자가 단톡방에서 “언제 돼?”라고 묻는 상황을 서비스 UI 조각으로 보여줄 것
- 기능 카드 3개 나열보다 실제 흐름을 보여줄 것: **초대 링크 → 시간 선택 → 추천 결과 → 확정**
- 모바일 참여자 시간 선택 화면을 핵심 화면으로 우선 설계
- 시간 슬롯은 터치하기 쉬운 크기와 명확한 상태 구분을 유지
- 가능/애매/불가 상태는 색과 텍스트를 함께 사용해 접근성을 확보

### 컴포넌트 기준
- 큰 radius, 얇은 border, 거의 없는 그림자
- 버튼은 Forest 중심, Poppy 버튼 남용 금지
- 아이콘은 line icon 계열, stroke 1.75~2px
- 카드 배경은 흰색, 구분은 border 중심
- 텍스트는 Pretendard, 제목은 자간 좁게, 본문은 행간 넉넉하게

### 브랜드 톤
- 친근하지만 감성 과잉 금지
- “스케줄 매칭을 시작합니다” 같은 기계적인 표현 금지
- “가능한 시간을 골라주세요”, “가장 잘 맞는 시간을 찾았어요”처럼 사람이 이해하기 쉬운 문장 사용
