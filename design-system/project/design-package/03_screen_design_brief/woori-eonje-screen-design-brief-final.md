# 우리 언제? 화면 디자인 요청서

## 1. 목적

이 문서는 **우리 언제?** 서비스의 실제 화면 디자인을 Claude Design에 요청하기 위한 기준서이다.

이미 확정된 로고, 파비콘, 컬러, 폰트, 컴포넌트 무드를 유지하면서, 화면별 UX 목적과 필수 구성 요소를 명확히 전달하는 것을 목표로 한다.

디자인 시스템 기준:
- 로고: 차콜 워드마크 + Poppy 물음표
- 파비콘: Poppy 말풍선 + 물음표
- 폰트: Pretendard
- 메인 컬러: Forest `#1A9562`
- 포인트 컬러: Poppy `#FF6B6B`
- 보조 그래픽 컬러: Baby Blue `#D6E7FF`, Lavender `#E6DBF7`
- 배경: 쿨톤 라이트그레이 `#F6F8FA`
- 기본 표면: White `#FFFFFF`
- 기본 라인: `#E5E7EB`

---

## 2. 서비스 요약

**우리 언제?**는 기간 기반 모임 시간 조율 서비스다.

모임장이 조율 기간과 예상 소요 시간만 설정하면, 참여자들이 가능한 날짜와 시간대를 입력하고, 시스템이 가장 많이 겹치는 시간대를 추천한다.

핵심 흐름:

```txt
초대 링크 공유
→ 참여자 시간 선택
→ 가능 / 애매 / 불가 응답 수집
→ 가장 많이 겹치는 시간 추천
→ 일정 확정
→ 공유 및 캘린더 추가
```

---

## 3. 전체 디자인 방향

### 핵심 무드

```txt
Cool Playful Utility
Clean Pop, Limited Color
Fresh Pastel Scheduling
```

깔끔하고 실용적인 일정 도구이지만, 너무 딱딱한 업무툴처럼 보이면 안 된다.  
10~30대가 친구 모임, 스터디, 사이드프로젝트, 가벼운 회의 일정을 조율할 때 부담 없이 사용할 수 있는 밝고 경쾌한 인상이 필요하다.

### 디자인 원칙

- 쿨톤 화이트 / 라이트그레이 기반
- Forest Green을 주요 액션 컬러로 사용
- Poppy는 로고 물음표, 파비콘, 작은 강조 포인트에만 제한적으로 사용
- Baby Blue와 Lavender는 배경 도형, 빈 상태 그래픽, 보조 장식에만 사용
- 카드는 흰색 배경 + 얇은 라인 + 큰 radius 중심
- 그림자는 거의 쓰지 않고 border와 여백으로 구분
- 시간 슬롯, 말풍선, 둥근 도형을 통해 서비스 고유의 리듬감 표현
- 기능 카드 3개 나열식 랜딩보다 실제 사용 흐름을 보여줄 것

## 4. 피해야 할 디자인 방향

```txt
- 일반적인 AI SaaS 랜딩페이지 느낌
- 3D 오브젝트 중심
- 과한 그라데이션 배경
- 기능 카드 3개만 나열하는 구성
- 추상적인 대시보드 목업 중심 구성
- 누리끼리한 베이지 / 크림 배경
- 캐릭터 중심 디자인
- 캘린더 아이콘 반복 사용
- 기업 로고 나열
- 요금제 / FAQ 중심의 상업형 랜딩 템플릿
- 너무 감성적인 다이어리 앱 분위기
```

이 서비스는 “예쁜 생산성 앱”보다 **단톡방에서 흩어진 가능 시간을 정리해주는 실제 흐름**이 보여야 한다.

| 구분 | 크기 | 굵기 | 행간 | 자간 |

| Heading 2 | 24px | 700 | 1.4 | -0.035em |
| Heading 3 | 20px | 700 | 1.45 | -0.03em |

## 10. 시간 슬롯 UI 기준

시간 선택 화면은 서비스의 핵심이다.  
모바일 터치 사용성을 최우선으로 한다.

### 기본 슬롯

```txt
Background: #FFFFFF
Border: 1px solid #E5E7EB
Text: #333333
Radius: 12px~14px
Min height: 56px 이상
```

### 가능

```txt
Background: #EAF7F1 또는 #1A9562
Border: #1A9562
Text: #1A9562 또는 #FFFFFF
```

### 애매

```txt
Background: #FFF7E8
Border: #F5AB54
Text: #B66A00
```

### 불가

```txt
Background: #F3F4F6
Border: #D1D5DB
Text: #9CA3AF
```

### 선택 UX

- 상단에서 현재 선택 모드 선택: 가능 / 애매 / 불가
- 슬롯을 누르면 현재 모드로 변경
- 다시 누르면 선택 해제
- 빠른 선택 기능 제공
- 선택 완료 버튼은 모바일 하단 고정

# 11. 화면별 디자인 요청

## 11-1. 모바일 시간 선택 화면

### 화면 목적

참여자가 초대 링크로 들어와 자신의 가능한 시간을 빠르게 선택하고 제출하는 화면이다.

### 핵심 UX

- 회원가입 없이도 쉽게 시작할 수 있어야 함
- 날짜와 시간이 많아도 부담스럽지 않게 보여야 함
- 가능 / 애매 / 불가 상태를 헷갈리지 않아야 함
- 모바일 터치로 쉽게 선택 가능해야 함
- 제출 전 내가 선택한 상태를 요약해서 확인할 수 있어야 함

### 필수 요소

```txt
- 상단 모임 정보 요약
- 날짜 선택 탭 또는 날짜 카드
- 현재 선택 모드 토글: 가능 / 애매 / 불가
- 시간 슬롯 리스트
- 빠른 선택 버튼
  - 평일 저녁 가능
  - 주말 오후 가능
  - 전체 초기화
- 선택 현황 요약
- 하단 고정 제출 버튼
- 임시 저장 또는 제출 완료 안내
```

### 상태

```txt
기본 상태
선택 중 상태
응답 제출 완료 상태
응답 마감 상태
기존 응답 수정 상태
```

---

## 11-2. 추천 결과 화면

### 화면 목적

모임장이 참여자들의 응답을 바탕으로 추천 시간 TOP 5를 확인하고, 최종 시간을 확정하는 화면이다.

### 핵심 UX

- 1순위 추천 시간이 가장 먼저 보여야 함
- 왜 추천됐는지 가능 / 애매 / 불가 인원으로 이해 가능해야 함
- 필수 참석자 반영 여부가 보여야 함
- 확정 버튼이 명확해야 함
- 추천 결과가 없는 경우 조건 완화 안내가 필요함

### 필수 요소

```txt
- 추천 시간 TOP 5 카드
- 1순위 추천 카드 강조
- 가능 / 애매 / 불가 인원 수
- 필수 참석자 반영 여부
- 참여자별 응답 현황
- 모임장 전용 확정 버튼
- 추천 결과 없음 상태
```

### 카드 구조 예시

```txt
1순위
6.8 (토) 14:00 ~ 16:00
가능 5명 · 애매 1명 · 불가 0명
필수 참석자 모두 가능
[이 시간으로 확정]
```

## 11-3. 모임 생성 Wizard

### 화면 목적

모임장이 조율 조건을 부담 없이 단계별로 입력하는 화면이다.

### 핵심 UX

- 한 화면에 모든 입력을 몰아넣지 않음
- 질문형 문장으로 단계별 입력을 유도
- 입력 완료 후 초대 링크를 쉽게 공유 가능해야 함
- 조율 기간, 예상 소요 시간, 응답 마감일 관계가 명확해야 함

### 단계

```txt
Step 1. 어떤 모임인가요?
- 모임명
- 설명
- 모임 성격: 친구 / 스터디 / 비즈니스

Step 2. 언제 사이에서 고를까요?
- 조율 시작일
- 조율 종료일
- 응답 마감일

Step 3. 얼마나 만날 예정인가요?
- 예상 소요 시간
- 선택 가능한 시간대

Step 4. 초대 링크를 공유해요
- 초대 링크
- 복사 버튼
- 공유 안내

Step 5. 응답을 기다리고 추천을 확인해요
- 참여자 응답 현황
- 추천 결과로 이동
```

## 11-4. 초대 참여 화면

### 화면 목적

비회원 참여자가 초대 링크를 열고, 모임 정보를 확인한 뒤 닉네임을 입력하고 참여를 시작하는 화면이다.

### 필수 요소

```txt
- 로고
- 모임명
- 모임 설명
- 조율 기간
- 예상 소요 시간
- 응답 마감일
- 닉네임 입력
- 참여 시작 버튼
- 로그인 없이 참여 가능 안내
```

### 문장 톤

```txt
6월 전시 모임에 초대되었어요.
닉네임만 입력하면 가능한 시간을 고를 수 있어요.
```

## 11-5. 랜딩 / 스플래시 화면

### 화면 목적

서비스의 첫인상과 문제 해결 흐름을 보여주고, 모임 만들기 CTA로 유도한다.

### 핵심 방향

일반적인 SaaS 랜딩처럼 추상적인 대시보드 목업을 크게 보여주지 않는다.  
대신 “단톡방에서 언제 돼?”라는 상황이 시간 슬롯과 추천 카드로 정리되는 흐름을 보여준다.

### 필수 요소

```txt
- 로고
- 롤링 카피
  - 우리 언제 만날까?
  - 우리 언제 떠나지?
  - 우리 언제 회의해?
  - 우리 언제 모일까?
- 메인 카피
- 서브 카피
- 모임 만들기 CTA
- 흩어진 답변 → 시간 슬롯 → 추천 시간 흐름
```

### 메인 카피 후보

```txt
언제 되냐는 말,
다시 정리하지 않아도 되게.

모두의 가능한 시간을 모아,
가장 잘 맞는 시간을 찾아요.
```

확정된 일정을 참여자들이 다시 확인하고 캘린더에 추가하거나 공유할 수 있는 화면이다.

### 필수 요소

## 11-8. 로그인 / 회원가입

### 화면 목적

모임장을 위한 간단한 인증 화면이다. 참여자는 비회원 참여가 가능하므로, 로그인 화면은 과하게 강조하지 않는다.

### 필수 요소

```txt
- 로고
- 이메일
- 비밀번호
- 로그인 버튼
- 회원가입 이동
- 모임 생성은 로그인 필요 안내
```

```txt
- 아직 만든 모임이 없어요
- 아직 응답한 사람이 없어요
- 모두가 가능한 시간이 없어요
```

표현 방식:
- 작은 파스텔 도형
- 명확한 안내 문구
- 다음 행동 버튼

## Error

```txt
- 초대 링크가 만료되었습니다
- 존재하지 않는 초대 링크입니다
- 응답 기간이 종료되었습니다
- 이미 일정이 확정된 모임입니다
- 일시적으로 정보를 불러오지 못했습니다
```

표현 방식:
- 과한 경고 화면 금지
- Poppy 또는 Error 색상은 작은 포인트로만 사용
- 가능한 다음 행동 제공

# 14. Claude Design 작업 프롬프트

아래 내용을 Claude Design에 그대로 전달한다.

```txt
우리 언제? 서비스의 화면 디자인을 제작해줘.

서비스 설명:
우리 언제?는 기간 기반 모임 시간 조율 서비스다.
모임장이 조율 기간과 예상 소요 시간만 설정하면, 참여자들이 가능한 날짜와 시간대를 입력하고, 시스템이 가장 많이 겹치는 시간대를 추천한다.
친구 모임, 스터디, 사이드프로젝트, 가벼운 회의 등 일상적인 모임 조율에 사용된다.

디자인 시스템:
- 로고: 차콜 워드마크 + Poppy 물음표
- 파비콘: Poppy 말풍선 + 물음표
- 폰트: Pretendard
- Primary: Forest #1A9562
- Accent: Poppy #FF6B6B
- Background: #F6F8FA
- Surface: #FFFFFF
- Line: #E5E7EB
- Text Primary: #333333
- Text Secondary: #6B7280
- 보조 그래픽 컬러: Baby Blue #D6E7FF, Lavender #E6DBF7

전체 무드:
깔끔한 쿨톤 화이트 기반의 서비스 UI.
딱딱한 업무툴은 아니지만, 감성 다이어리 앱처럼 흐르지도 않게.
색은 많이 쓰지 않고 Forest와 Poppy를 제한적으로 사용.
카드는 흰색 배경, 얇은 border, 큰 radius, 거의 없는 그림자.
말풍선, 물음표, 시간 슬롯, 둥근 도형으로 서비스만의 리듬감을 만들 것.

중요:
일반적인 AI SaaS 랜딩페이지처럼 만들지 말 것.
3D 오브젝트, 과한 그라데이션, 기능 카드 3개 나열, 추상적인 대시보드 목업 중심 구성은 피할 것.
이 서비스의 핵심은 단톡방에서 흩어진 가능한 시간 답변을 정리하고, 가장 많이 겹치는 시간을 추천하는 흐름이다.
따라서 화면은 초대 링크, 시간 슬롯 선택, 추천 결과, 일정 확정이라는 실제 사용 흐름이 보이도록 설계할 것.

우선 제작할 화면:
1. 모바일 시간 선택 화면
2. 추천 결과 화면
3. 모임 생성 Wizard
4. 초대 참여 화면
5. 랜딩 / 스플래시
6. 내 모임 목록
7. 최종 요약 화면
8. 로그인 / 회원가입

특히 모바일 시간 선택 화면과 추천 결과 화면을 가장 중요하게 다뤄줘.
시간 슬롯은 터치하기 쉬운 크기여야 하고, 가능 / 애매 / 불가 상태는 색과 텍스트를 함께 사용해서 명확하게 구분해줘.
```

# 15. 추가 요청 조건

Claude Design에 화면 디자인을 요청할 때 아래 조건도 함께 전달한다.  
이 조건들은 단순히 예쁜 화면이 아니라, 실제 서비스로 개발 가능한 UI와 포트폴리오용 완성도를 높이기 위한 기준이다.

## 15-1. 모바일 / 데스크톱 대응

```txt
각 화면은 모바일 우선으로 설계하되, 데스크톱 확장 레이아웃도 함께 제안해줘.
특히 시간 선택 화면은 모바일 기준을 우선하고, 추천 결과와 모임 목록은 데스크톱에서도 정보가 잘 보이도록 구성해줘.
```

기준:
- 참여자 화면은 모바일 사용성을 최우선으로 한다.
- 모임장 화면은 데스크톱에서도 관리하기 쉬워야 한다.
- 모바일에서는 하단 고정 CTA 사용을 고려한다.
- 데스크톱에서는 카드, 패널, 사이드 요약 영역을 활용해 정보 구조를 넓게 펼친다.

## 15-2. 핵심 화면 2~3안 비교

```txt
핵심 화면인 모바일 시간 선택 화면, 추천 결과 화면, 랜딩 화면은 각각 2~3가지 레이아웃 방향으로 제안해줘.
각 안마다 장단점과 어떤 사용자 흐름에 적합한지 함께 설명해줘.
```

비교 기준:
- 사용자가 다음 행동을 바로 이해할 수 있는가
- 모바일에서 터치하기 쉬운가
- 서비스 차별점이 화면에서 보이는가
- 정보가 과하게 많거나 산만하지 않은가
- 일반적인 AI SaaS 템플릿처럼 보이지 않는가

## 15-3. 사용자 플로우 연결 설계

```txt
화면을 단독 시안이 아니라 하나의 사용자 플로우로 연결해서 설계해줘.
예: 초대 링크 접속 → 닉네임 입력 → 시간 선택 → 제출 완료 → 추천 결과 확인 → 일정 확정 → 최종 요약.
```

주요 플로우:
```txt
모임장 플로우:
로그인 → 내 모임 목록 → 모임 생성 Wizard → 초대 링크 공유 → 추천 결과 확인 → 일정 확정 → 최종 요약 공유

참여자 플로우:
초대 링크 접속 → 모임 정보 확인 → 닉네임 입력 → 시간 선택 → 제출 완료 → 확정 일정 확인 → 캘린더 추가
```

## 15-4. 상태 화면 포함

```txt
각 주요 화면은 기본 상태만 만들지 말고 Loading, Empty, Error 상태도 함께 설계해줘.
특히 초대 링크 만료, 응답 마감, 추천 결과 없음, 참여자 0명 상태를 포함해줘.
```

반드시 포함할 상태:
```txt
Loading
- 모임 정보 조회 중
- 시간 슬롯 조회 중
- 추천 결과 계산 중

Empty
- 아직 만든 모임이 없음
- 아직 응답한 사람이 없음
- 추천 가능한 시간이 없음

Error
- 초대 링크 만료
- 존재하지 않는 초대 링크
- 응답 마감
- 이미 확정된 모임
- API 호출 실패
```

상태 화면 원칙:
- 과한 일러스트보다 작은 파스텔 도형과 명확한 문장을 사용한다.
- 오류 상태에서도 다음 행동을 제공한다.
- Poppy 또는 Error 색상은 작은 포인트로만 사용한다.
- 빈 상태는 “무엇을 하면 되는지”를 함께 안내한다.

## 15-5. 컴포넌트 상태값 정의

```txt
각 컴포넌트는 default, hover, active, disabled, error 상태를 함께 정의해줘.
버튼, 입력창, 시간 슬롯, 상태 배지, 추천 카드, 모임 카드 중심으로 정리해줘.
```

상태값이 필요한 컴포넌트:
```txt
Button
- default
- hover
- active
- disabled
- loading

Input
- default
- focus
- filled
- error
- disabled

Time Slot
- default
- available
- maybe
- unavailable
- selected
- disabled

Status Badge
- collecting
- ready to confirm
- confirmed
- closed
- expired

Recommendation Card
- normal
- first rank
- selected
- unavailable
```

## 15-6. 접근성 기준

```txt
가능 / 애매 / 불가 상태는 색상만으로 구분하지 말고 텍스트, 라벨, 아이콘 또는 패턴을 함께 사용해줘.
텍스트 대비가 낮아지지 않도록 접근성을 고려해줘.
```

접근성 원칙:
- 상태는 색상 + 텍스트 라벨을 함께 사용한다.
- 모바일 터치 영역은 충분한 높이를 확보한다.
- 주요 CTA는 배경과 대비가 분명해야 한다.
- 오류 문구는 색상만으로 표현하지 않고 문장을 함께 제공한다.
- Disabled 상태는 너무 흐리게 만들어 읽기 어려워지지 않도록 한다.

## 15-7. AI 디자인 느낌 방지

```txt
AI 서비스 랜딩처럼 보이는 추상 카드, 3D 오브젝트, 과한 그라데이션, 의미 없는 통계 수치, 가짜 대시보드 목업은 사용하지 말아줘.
실제 사용자가 약속 시간을 정하는 과정이 화면에서 보여야 해.
```

사용 금지에 가까운 요소:
```txt
- 의미 없는 3D 오브젝트
- 추상적인 플로팅 카드 과다 사용
- 가짜 통계 수치
- “10,000+ users” 같은 근거 없는 지표
- 기업 로고 나열
- 요금제 섹션 중심 랜딩
- 과도한 glassmorphism
- 보라/파랑 그라데이션 SaaS 배경
- AI 대시보드처럼 보이는 차트 목업
```

```txt
이 서비스의 핵심은 단톡방에서 흩어진 가능한 시간 답변을 정리하고, 가장 많이 겹치는 시간을 추천하는 흐름이다.
따라서 화면은 초대 링크, 시간 슬롯 선택, 추천 결과, 일정 확정이라는 실제 사용 흐름이 보이도록 설계할 것.

우선 제작할 화면:
1. 모바일 시간 선택 화면
2. 추천 결과 화면
3. 모임 생성 Wizard
4. 초대 참여 화면
5. 랜딩 / 스플래시
6. 내 모임 목록
7. 최종 요약 화면
8. 로그인 / 회원가입

요청 조건:
- 각 화면은 모바일 우선으로 설계하되, 데스크톱 확장 레이아웃도 함께 제안
- 모바일 시간 선택 화면, 추천 결과 화면, 랜딩 화면은 각각 2~3가지 레이아웃 방향 제안
- 각 안마다 장단점과 어떤 사용자 흐름에 적합한지 설명
- 화면을 단독 시안이 아니라 하나의 사용자 플로우로 연결해서 설계
- 기본 상태만 만들지 말고 Loading, Empty, Error 상태도 함께 설계
- 버튼, 입력창, 시간 슬롯, 상태 배지, 추천 카드, 모임 카드의 상태값 정의
- 가능 / 애매 / 불가 상태는 색상만으로 구분하지 말고 텍스트, 라벨, 아이콘 또는 패턴을 함께 사용
- 각 화면에 들어갈 실제 문구도 함께 작성
- 개발자가 컴포넌트화하기 쉽도록 컴포넌트 이름, 사용 위치, 상태값, spacing, radius, typography token을 함께 표기

특히 중요한 화면:
모바일 시간 선택 화면과 추천 결과 화면을 가장 중요하게 다뤄줘.
시간 슬롯은 터치하기 쉬운 크기여야 하고, 가능 / 애매 / 불가 상태는 색과 텍스트를 함께 사용해서 명확하게 구분해줘.

최종 산출물은 아래 순서로 정리해줘.
1. 전체 디자인 콘셉트 요약
2. 주요 화면 플로우
3. 화면별 시안
4. 화면별 UX 의도
5. 컴포넌트 목록
6. 컴포넌트 상태값
7. 마이크로카피
8. 반응형 기준
9. 접근성 고려사항
10. 개발 전달 메모

단순히 예쁜 화면이 아니라, 실제 서비스로 개발 가능한 UI를 기준으로 설계해줘.
각 화면은 사용자가 다음 행동을 바로 이해할 수 있어야 하고, 화면 간 흐름이 자연스럽게 이어져야 해.
포트폴리오에 넣었을 때 “문제 정의 → UX 설계 → UI 시스템 → 구현 가능성”이 드러나는 결과물로 정리해줘.
```

# 18. 디자인 결과 평가 체크리스트

```txt
□ 랜딩 화면이 추상적인 SaaS 목업이 아니라 실제 사용 맥락을 보여주는가?
```

## 18-2. UI/UX 평가

```txt
□ 모바일 시간 슬롯이 실제로 누르기 쉬운 크기인가?
□ 가능 / 애매 / 불가 상태가 색 없이도 텍스트로 구분되는가?
```

# 19. 1차 / 2차 제작 범위

Claude Design에 한 번에 모든 화면을 동일한 깊이로 요청하지 않고, 핵심 화면부터 퀄리티를 확보한다.

## 19-1. 1차 필수 화면

```txt
1. 모바일 시간 선택 화면
2. 추천 결과 화면
3. 모임 생성 Wizard
4. 초대 참여 화면
```

1차 화면은 실제 서비스 차별점이 가장 잘 드러나는 화면이다.  
각 화면은 기본 상태뿐 아니라 Loading / Empty / Error 상태도 함께 요청한다.

## 19-2. 2차 확장 화면

```txt
1. 랜딩 / 스플래시
2. 내 모임 목록
3. 최종 요약 화면
4. 로그인 / 회원가입
```

2차 화면은 1차 핵심 UI가 확정된 뒤 그 스타일을 확장 적용한다.  
랜딩은 독립적으로 예쁘게 만들기보다 시간 선택 UI와 추천 결과 UI 조각을 활용해 서비스 흐름이 보이도록 구성한다.

## 19-3. 최종 작업 순서

```txt
1. 디자인 시스템 확인
2. 1차 핵심 화면 2~3안 제작
3. 시간 선택 / 추천 결과 화면 우선 평가
4. 선택한 방향 기준으로 수정
5. 2차 화면 확장
6. 상태 화면 / 컴포넌트 상태값 정리
7. 개발 전달용 컴포넌트 목록 확정
```
